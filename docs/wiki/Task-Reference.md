# Task Reference (`sbom-tool@1`)

Source of truth: `task/task.json` (schema-validated inputs) and `task/index.ts` (what actually
consumes them). Task id `79d7e0df-bd9a-4658-9897-ae059fc992c5`, friendly name "SBOM Tool",
`minimumAgentVersion: 3.232.1`, runtime handler `Node20_1`.

## Command support

| `command` value | Status                                                                                                                                                                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `generate`      | ✅ implemented — runs `sbom-tool generate` on the agent                                                                                                                                                                                                                                          |
| `import`        | ✅ implemented — attaches an SBOM manifest that was **already generated by another tool**, skipping the `sbom-tool` CLI entirely. See [§ Import command](#import-command) below and [Manual Private Install](Manual-Private-Install.md) / [UI Report Tab](UI-Report-Tab.md) for why this exists. |
| `validate`      | ❌ stub — `task/index.ts` throws `Not implemented`                                                                                                                                                                                                                                               |
| `redact`        | ❌ stub — `task/index.ts` throws `Not implemented`                                                                                                                                                                                                                                               |

## Import command

Added so this extension's report tab can be used to view SBOMs produced by other tools (syft,
trivy, cyclonedx-to-spdx, a previous pipeline run, etc.) without ever running `sbom-tool` itself —
see `SbomTool.importAsync` in `task/utils/sbomTool.ts`. It reuses the exact same post-generation
pipeline as `generate` (security-advisory enrichment, XLSX/SVG export, build-attachment), just
starting from an existing file instead of `sbom-tool`'s own output.

| Name                     | Type      | Default            | Notes                                                                                                                                                                                                                                |
| ------------------------ | --------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `importManifestFilePath` | multiLine | _(none, required)_ | One path/glob per line to existing SPDX 2.x JSON manifest file(s). Each resolved file is imported and attached as its own SBOM — same multi-file behavior as `buildSourcePath` under `generate`. Visible only when `command=import`. |

Shared with `generate` (visible for **both** commands — the `package` group and `additionalComponentDetectorArgs`/`externalDocumentReferenceList` are hidden under `import` instead, since they're meaningless without an actual scan):

- `manifestOutputPath` — same meaning; defaults to `$(Build.ArtifactStagingDirectory)` when omitted under `import` (there's no `buildArtifactPath` to fall back to).
- `enableManifestSpreadsheetGeneration`, `enableManifestGraphGeneration`
- `fetchSecurityAdvisories` (+ `gitHubConnection`/`gitHubAccessToken`)
- `vulnerabilitiesSource` — see [§ `vulnerabilitiesSource` format](#vulnerabilitiessource-format) below.

Unlike `generate` (which always writes `_manifest/spdx_2.2/...`, since that's what `sbom-tool` itself always emits), `import` derives the folder's version segment from the **imported document's own** `spdxVersion` field (e.g. an SPDX 2.3 import lands under `_manifest/spdx_2.3/...`).

```yaml
- task: sbom-tool@1
  displayName: 'Import externally-generated SBOM'
  inputs:
    command: 'import'
    importManifestFilePath: '$(Pipeline.Workspace)/**/*.spdx.json'
    enableManifestSpreadsheetGeneration: true
    fetchSecurityAdvisories: true
    gitHubConnection: 'GitHub Advisory Database Connection'
```

## Inputs

### Package Information group

| Name                            | Type   | Default                    | Notes                                                                                                                                                                                |
| ------------------------------- | ------ | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `packageName`                   | string | `$(Build.Repository.Name)` | Defaults to the repo name for a single `buildSourcePath`; when `buildSourcePath` is a glob matching multiple directories, each one is named from its own directory basename instead. |
| `packageVersion`                | string | `$(Build.BuildNumber)`     | Falls through to `'0.0.0'` if neither the input nor `Build.BuildNumber` resolve.                                                                                                     |
| `packageSupplier`               | string | `$(System.CollectionId)`   | Falls through to `'Unknown'`. Also used to derive the default namespace URI hostname (see below).                                                                                    |
| `packageNamespaceUriBase`       | string | _(empty)_                  | Defaults to `https://{supplierHostnameified}.com` — the supplier string has whitespace turned into dashes, non-alphanumerics stripped, lowercased.                                   |
| `packageNamespaceUriUniquePart` | string | _(empty)_                  | Appended to the SPDX namespace URI; should be globally unique if set.                                                                                                                |

Hidden entirely under `command=import` (`visibleRule: command=generate`) — meaningless when there's
no actual scan happening.

### `vulnerabilitiesSource` format

Added for cases where `fetchSecurityAdvisories` can't be used — e.g. a `gitHubConnection` using an
auth scheme the task's token resolution doesn't support (`InstallationToken`, see
[Troubleshooting](Troubleshooting.md)), or when vulnerability data comes from another scanner
entirely (Trivy, `npm audit`, `dotnet list package --vulnerable`, a custom script, etc). Implemented
in `task/utils/spdx/addSpdxPackageVulnerabilitiesFromFile.ts`; shares the same external-ref writing
logic (`addSecurityAdvisoryExternalRefsToPackage`) as the GHSA-fetch path in
`task/utils/spdx/addSpdxPackageSecurityAdvisories.ts`, so matched vulnerabilities show up identically
in the "SBOM" report tab regardless of which source they came from.

Each file resolved by `vulnerabilitiesSource` must contain a JSON array of objects matching
`IExternalVulnerability` (`shared/ghsa/models/externalVulnerability.ts`):

| Field                    | Required | Notes                                                                                                                                                                                                                                                    |
| ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packageName`            | ✅       | Matched case-insensitively against SBOM package `name`.                                                                                                                                                                                                  |
| `packageVersion`         |          | If omitted, the vulnerability is applied to every SBOM package matching `packageName`, regardless of version.                                                                                                                                            |
| `id`                     | ✅       | GHSA id, CVE id, or any other identifier string from your scanner.                                                                                                                                                                                       |
| `cveId`                  |          | Set this in addition to `id` if `id` isn't already a CVE id.                                                                                                                                                                                             |
| `severity`               | ✅       | One of `LOW`, `MODERATE`, `HIGH`, `CRITICAL` (`SecurityAdvisorySeverity`) — must match exactly.                                                                                                                                                          |
| `summary`                |          | One-line title.                                                                                                                                                                                                                                          |
| `description`            |          | Longer free-text description.                                                                                                                                                                                                                            |
| `url`                    |          | Link to the advisory page. If omitted, a best-effort link is derived from `cveId` (NVD) or a `GHSA-*` `id` (GitHub Advisories); otherwise a synthetic `urn:vulnerability:...` identifier is used so the entry still dedupes correctly in the report tab. |
| `vulnerableVersionRange` |          | e.g. `"<=1.8.4"` or `"20.0.0-next.0 - 20.3.26"`.                                                                                                                                                                                                         |
| `fixedVersion`           |          | First version that fixes the vulnerability, if known.                                                                                                                                                                                                    |
| `cvssScore`              |          | Numeric CVSS score.                                                                                                                                                                                                                                      |
| `publishedAt`            |          | ISO 8601 timestamp.                                                                                                                                                                                                                                      |

Package matching is by name (+ optional version) only — there's no purl/ecosystem matching, so
`packageName` values from an `npm audit` or `dotnet list package` report should match SBOM package
names directly (e.g. the bare npm package name, or the NuGet package id). A vulnerability that
doesn't match any SBOM package is silently skipped (the task logs a single summary count of matched
vs. unmatched entries); it never fails the task.

```yaml
- task: sbom-tool@1
  displayName: 'Import externally-generated SBOM'
  inputs:
    command: 'import'
    importManifestFilePath: '$(Pipeline.Workspace)/**/*.spdx.json'
    vulnerabilitiesSource: |
      $(Pipeline.Workspace)/**/npm-vulnerabilities.json
      $(Pipeline.Workspace)/**/dotnet-vulnerabilities.json
```

## sbom-tool auto-install behavior

`SbomTool.getToolPathAsync()` in `task/utils/sbomTool.ts` resolution order:

1. `sbom-tool` already on `PATH` (via `which`).
2. Already present at `{Agent.ToolsDirectory}/sbom-tool` (Linux/macOS) or
   `{Agent.ToolsDirectory}\sbom-tool.exe` (Windows).
3. Otherwise, install it:
   - **Linux/macOS**: `brew install sbom-tool[@version]` if Homebrew is present, else download the
     matching `sbom-tool-linux-{arch}` binary from the
     [microsoft/sbom-tool releases](https://github.com/microsoft/sbom-tool/releases) via `curl`
     and `chmod +x` it.
   - **Windows**: `winget install Microsoft.SbomTool [--version x]` if winget is present, else
     download `sbom-tool-win-{arch}.exe` via PowerShell `Invoke-WebRequest`.

The task's `version` input (not shown above — it's read directly via `getInput('version', false)`
in `task/index.ts`, not declared as a distinct entry in `task.json`'s `inputs`) pins the
`sbom-tool` CLI version to install/use.

## YAML examples

Minimal:

```yaml
- task: sbom-tool@1
  displayName: 'Generate project SBOM manifest'
  inputs:
    command: 'generate'
```

Full, matching the [`README.md`](../../README.md) example (spreadsheet + graph + license +
security-advisory enrichment):

```yaml
- task: sbom-tool@1
  displayName: 'Generate project SBOM manifest'
  inputs:
    command: 'generate'
    buildSourcePath: '$(Build.SourcesDirectory)'
    buildArtifactPath: '$(Build.ArtifactStagingDirectory)'
    enableManifestSpreadsheetGeneration: true
    enableManifestGraphGeneration: true
    enablePackageMetadataParsing: true
    fetchLicenseInformation: true
    fetchSecurityAdvisories: true
    gitHubConnection: 'GitHub Advisory Database Connection'
    packageSupplier: 'MyOrganisation'
    packageName: 'MyPackage'
    packageVersion: '$(Build.BuildNumber)'
```

Multiple source directories (one SBOM per match), each artifact directory resolved relative to its
own source directory:

```yaml
- task: sbom-tool@1
  inputs:
    command: 'generate'
    buildSourcePath: |
      $(Build.SourcesDirectory)/services/*
    buildArtifactPath: |
      $(Build.ArtifactStagingDirectory)/**
    manifestOutputPath: '$(Build.ArtifactStagingDirectory)'
```
